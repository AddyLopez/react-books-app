# React Books App

## Description

A Single Page Application (SPA) coded in React with CRUD functionality and data persistence through integration with JSON Server API. The application enables the user to add a book title, modify it, or delete it from the list of books rendered to the screen. Randomized images (unrelated to books) are generated by Picsum for each item as a minor UI consideration.

## Learning objectives attained

For me to gain a more sophisticated understanding of different approaches (with differing tradeoffs) to coding React applications, this project underwent deliberate iterations with three versions in mind:

1. Version one focused on implementing CRUD functionality through React's state management without data persistence. It put into practice reusable components with JSX, event and form handling, conditional rendering, plus the flow of data from parent(s) to children via the passing of props and from children up to parent(s) via callbacks. I learned more about how to deal successfully with state changes to arrays and objects, which pose special challenges in React not posed by strings, Booleans, and numbers.

2. Version two refactored the application to enable data persistence with the external API JSON Server. When a user creates, edits, or deletes a book from the list, the API stores those changes and the local data get updated to reflect those changes on the user interface. I tested the endpoints of GET, POST, PUT, and DELETE requests using the VS Code extension REST Client. This version makes use of the useEffect React hook, Axios, and asynchronous JavaScript data fetching, while considering data integrity when rendering books so that there are no discrepancies between the data stored and data displayed, especially if separate instances of the app are running and making changes to the data.

3. Version three introduces centralized state, using React Context, in conjunction with the data persistence from version two. An implicit conceptual distinction is made between application state, which provides data useful to the entire application, and component state, which provides data useful to local components but not to the entire application. Context and props are both used, but the use of props in this version is far more constrained and the flow of data is less verbose through this refactor. New techniques employed include React's context provider, the useContext and useCallback hooks, and a custom hook. This iteration of the application also brought me to a deeper understanding of the useEffect hook and a very common issue flagged by ESLint that arises due to the possibility of stale variables in memory between renders, which could lead to future bugs or infinite re-renderings.
